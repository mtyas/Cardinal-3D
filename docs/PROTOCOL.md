# Local bridge v1

VR unplugging uses `disconnect_cable` with `cable_id`, `input_module`, and `input_port`. The host removes exactly that cable after validating its current input endpoint and records a native undo action. Missing or changed cables fail without removing another connection. A pulled plug released over empty space disconnects; tracking loss or an unpulled click preserves the cable. Output sockets continue to support creating additional connections.

Every frame starts with a little-endian uint32 byte count, followed by a kind byte. Kind 1 contains UTF-8 JSON. Kind 2 contains uint32 JSON-header length, JSON header and top-down RGBA8 artwork. A client may request `surface_compression: "zstd"` in its hello. Compressed surfaces carry `encoding: "zstd"`; missing encoding means raw pixels. Decompressed size must equal width times height times four and is capped at 16 MiB. The frame count includes the kind byte. The maximum output frame and queue size is 24 MiB; commands are limited to 64 KiB.

The client sends `{op:"hello", version:1, token, request}`. The server replies with catalog, snapshot and acknowledgment messages. Commands carry a request number and the latest snapshot `generation`; acknowledgments report `ok` and an optional `error`. IDs and generations are strings to preserve integer precision. Module IDs are runtime identities; plugin/model slugs identify models. Parameter, light and input/output port IDs occupy separate namespaces.

Snapshots contain modules, recognized widget types and bindings, control values/limits, ports/channel counts, lights and colors, cable endpoints/colors, floating cable state, history labels, native overlay visibility and existing Cardinal audio CPU meters. Descriptors include `screens` for explicitly recognized live display regions, with constructor-established widget coordinates. Texture headers contain module ID (or `scene`), generation, width and height. Frontends discard textures from older generations. Creation, deletion and reload invalidate widget references and advance generation before acknowledgments.

`overlay_mode` is `none`, `menu` or `full`. For `menu`, only the native menu overlay is drawn into a transparent crop, including open submenus. Scene texture headers carry `origin_x`/`origin_y`; add this origin to crop-local pointer coordinates before sending scene interactions. `full` retains the complete scene for the explicit Original UI action and native module browser. Mode changes invalidate the scene surface cache and publish a fresh snapshot before rendering.

Commands: `pointer` (module or scene, x/y in native pixels, down/motion/up, GLFW button and modifier bits), `drag_delta`, `release`, `reset_hovered`, `disconnect_port`, `add`, `starter`, `audible_starter`, `remove`, `move_begin`, `move_delta`, `move_end`, `undo`, `redo`, `save`, `load`, `overlay`, `escape`, `scroll`, `key`, `text`, `describe_library`, `preview`, `preview_clear` and `heartbeat`. Save/load/report paths must be absolute. Library scans send progress and acknowledge when their report is written.

`preview` takes plugin/model slugs, creates an unregistered native module/widget and sends a `preview` descriptor plus one static surface with ID `preview/plugin/model`. There are at most sixteen preview widgets per session; `preview_clear`, disconnect or graphics shutdown releases them. Previews never step as active patch modules, enter the audio engine, or accept parameter/cable interaction commands. The frontend selects a preview and requests ordinary `add` for the exact plugin/model. Native module and control IDs are assigned only after insertion.

All commands execute in Cardinal's UI context. Original widgets remain alive and step normally. Interaction routes through Rack events and history actions. No bridge callback is installed in DSP or audio processing. Native parameter limits, switches, momentary controls, cable rules and menus remain authoritative.

Native surface descriptors include editable labels and MindMeld group-routing arrows without parameter IDs. Their IDs use a `surface-` prefix. Custom controls retain exact pointer coordinates rather than snapping to their centre. Surface clicks cannot start native module dragging; XR module placement remains restricted to its top strip. `parameter_choices` takes `module`, integer `param`, and local `x`/`y` to open the MixMaster group-routing chooser. It validates a bounded discrete quantity and records selections in native undo history.

Transport is nonblocking. Each UI poll reads at most 64 KiB and 64 commands; each flush sends at most 4 MiB. JSON state has priority over unsent artwork, without interrupting a partially transmitted frame. The Godot client bounds incoming frames and outgoing commands. Obsolete unsent snapshots and textures are replaced, while acknowledgments are reliable. Overflow or a three-second missing heartbeat disconnects and releases active gestures. Godot reconnects automatically.

`patch_cable` takes `output_module`, `output_port`, `input_module`, `input_port`, and an optional `replace_cable` ID. It validates sockets, replaces a cable occupying the destination input, and records all removals/addition as one history action. Repatching an existing input keeps its original cable intact until a valid release; cancelling changes nothing. The XR client renders the pending cable locally instead of relying on native pointer hover events.

`move_delta` accepts optional boolean `insert`. When true, native Rack insertion shifts intersecting neighbors; the move gesture records all affected positions in one undo action. The default retains nearest-free placement for older clients. XR previews the same row/left/right insertion algorithm locally while dragging the top strip, then commits only on release.

Surfaces use a separate NanoVG framebuffer and restore native viewport/framebuffer state and widget visibility. Recognized physical widgets are hidden only during texture capture; unsupported controls and illuminated composite switches keep their original surface. Unchanged pixel hashes avoid redundant transfers. `bridge/overrides.json` supports `plugin/model: "surface"` for a full fallback or `plugin/model/kind: "surface"` for a component-kind fallback. Unknown custom controls are never assigned invented semantics.

Current limits: the surface covers the entire module rather than separate display rectangles; static artwork is cached by Cardinal and unchanged transfers are suppressed, but capture still samples the full surface. The transport supports POSIX and Windows Winsock. Native dialogs that are external OS windows remain in the original Cardinal window. Keeping the original window visible is currently necessary for live surface redraws.

Catalog entries expose native `module_name`, `manufacturer` (plugin brand) and human-readable `tags` for frontend sorting and filtering. Control descriptors carry `visible`, including ancestor visibility. Rendered hardware and magnetic picking mirror it so overlapping alternate controls, such as Plaits LPG/Timbre/Morph, remain mutually exclusive.
